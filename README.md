# Image to Bouquet

> 给一张图片，得到一束真实能做出来、而且真正有花艺设计感的花。

`image-to-bouquet` 不会把原图“拼成一束花”。它会读取参考图里的 **色彩层级、视觉重心、冷暖关系、节奏、疏密和氛围**，再重新设计成一束正常的手绑花束。

```text
参考图片
  ↓
色彩 / 重心 / 对比 / 节奏 / 氛围
  ↓
脱离原图，重新做花艺构图
  ↓
真实手绑花束
  ↓
花束成品图 + 花艺师执行单
```

## 怎么用

安装 Skill 后，直接给 Codex 一张图片：

> 用 image-to-bouquet 把这张图转成一束花。

参考图可以是人物、风景、建筑、插画、海报、专辑封面或抽象图片。

## 核心原则

### 最终必须还是“一束花”

不会保留原图里的人脸、身体、建筑、物体、文字、Logo、线稿和具体轮廓，也不会用花朵拼成人像、物体、图案或场景。

判断很简单：

> 把原图藏起来以后，第一眼只能看到一束花，而不是“用花摆出来的某个东西”。

### 不是把颜色分块堆起来

好的结果不能只是：

> 左边一堆蓝紫 + 中间一堆浅色 + 右边一堆红橙

Skill 会重新做真正的花艺构图，包括：

- **主焦点**：有一个明确但不过分居中的视觉重点；
- **辅助层**：形成平衡，而不是左右机械镜像；
- **过渡层**：让两组主色自然交错，不出现生硬分界线；
- **动势**：通过真实线性花材、枝材和高低关系形成方向；
- **前后层次**：花头不会全部压成一张平面；
- **留白**：给花材呼吸空间，不做成密不透风的花墙；
- **节奏**：大小、高低、疏密有变化，而不是均匀铺满。

如果最终只是“按颜色填区域”，就应该重做。

### 保留构图关系，不保留主体形状

Skill 可以保留的是：

- 主色 / 次色 / 点缀色及大致比例；
- 左冷右暖、中心轻边缘重等宏观关系；
- 视觉重心和大致方向；
- 明暗、冷暖、饱和度对比；
- 疏密、节奏、留白和氛围。

不会保留人物脸型、五官位置、建筑轮廓、物体边缘等可以识别原图主体的信息。

### 先分析，再切断原图

分析完成后，Skill 会先生成一份只包含花材、配色和花艺构图的纯文字配方，再从零生成花束。

最终生成阶段不应继续把原图作为编辑底图、贴图、纹理或构图模板。

### 只用正常花艺材料

默认可见元素只有：

- 鲜花；
- 配叶和自然植物枝材；
- 必要时明确说明的干花 / 永生 / 染色 / 仿真植物材料；
- 普通花艺包装纸、内衬和丝带。

默认不加入：

- 可见铁丝、黑杆、珠针、几何骨架；
- 灯条、霓虹灯、灯棒或电子设备；
- 吊牌、卡片、标签、Logo、打印图片；
- 亚克力、水晶、模型、抽象装置等概念道具。

花艺铁丝可以作为隐藏固定结构使用，但不能拿来画线、连点或做视觉骨架。

### 色彩来自花本身

主要颜色必须来自真实花材、包装和丝带，而不是靠红蓝紫灯光把花“染”成参考图配色。

放到普通日光下，这束花的主要色彩关系仍然应该成立。

## 你会得到什么

### 1. 花束成品图

一张独立、清晰、真实的花店产品图。

默认控制在中小尺寸，不靠几十朵花和大量不同品种堆出视觉冲击。

### 2. 花艺师执行单

图片生成完成后，Skill 还必须给出对应的执行单，包括：

- 花束尺寸和结构；
- 主焦点 / 辅助 / 过渡的设计关系；
- 花材、配叶和数量；
- 包装和丝带；
- 简短制作顺序；
- 可替代材料；
- 成本等级；
- 最需要保留的视觉关系。

只返回图片、漏掉执行单，属于不完整结果。

## 最终目标

不是复制原图，也不是把颜色铺进一束花里，而是：

> **让人能感受到参考图的色彩和气质，同时得到一束本身就成立、真实可做、具有花艺层次和设计感的花束。**
