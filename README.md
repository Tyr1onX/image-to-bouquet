# Image to Bouquet

> 给一张图片，得到一束真实能做出来的花。

这是一个给 Codex / Agent 使用的简单 Skill。

它不会照搬参考图里的具体人物、建筑、Logo 或物体，而是读取图片中的 **色彩、构图、质感和氛围**，再把这些视觉关系转成一束现实可制作、成本可控的花束。

```text
参考图片
  ↓
色彩 / 构图 / 质感 / 氛围
  ↓
真实可制作的花束
  ↓
花束成品图 + 花艺师执行单
```

## 怎么用

安装本仓库中的 `SKILL.md`，然后直接给 Codex 一张图片，例如：

> 用 image-to-bouquet 把这张图转成一束花。

不需要提前指定花材。Skill 会先从图片中提取视觉关系，再决定花材、包装、结构和成本控制方式。

## 输出

一次完整结果只需要两个核心产物：

### 1. 花束成品图

- 一张独立、清晰的花束图片；
- 必须由原生图片生成工具直接生成；
- 只展示最终花束和简单背景；
- 不带原图缩略图、说明板、文字、拼贴或信息图；
- 花束必须看起来真的能被花艺师做出来。

### 2. 花艺师执行单

简要说明：

- 花束尺寸与结构；
- 使用的花材和配叶；
- 每种材料的大致数量；
- 包装纸、内衬、丝带等外部材料；
- 简短制作顺序；
- 可替代材料；
- 成本等级；
- 最需要保留的视觉特征。

图片和执行单必须描述 **同一束花**。

## 核心原则

### 视觉转译，而不是复制原图

```text
色彩 → 花材 / 包装 / 丝带
构图 → 花束轮廓 / 高低 / 重心 / 留白
质感 → 花材表面 / 配叶 / 包装材质
氛围 → 饱和度 / 密度 / 克制程度
```

### 现实可制作

默认不使用漂浮物、星球、模型、Logo、发光结构等难以复现的装饰。参考图里的具体物体只作为视觉关系来源，不直接塞进花束。

### 默认控制成本

除非特别说明，默认做中小尺寸花束：

- 约 3–5 类花材 / 配叶；
- 约 7–12 个主要花头或主枝；
- 能用包装、丝带和配叶完成的颜色关系，不额外堆花；
- 优先常见、容易采购的材料。

### 图片必须是原始生成结果

一个参考图对应一次独立图片生成。不能把拼贴图、信息图或截图里的小花束裁出来再当成最终结果。
