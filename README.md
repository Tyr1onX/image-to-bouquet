# Image to Bouquet

> 给一张图片，得到一束真实能做出来的花。

`image-to-bouquet` 会读取参考图里的 **色彩层级、粗略色彩分区、整体密度和氛围**，再把这些关系转译成一束正常、真实、可制作的花束。

它不会把原图里的人物、建筑、物体、文字、Logo、线稿或轮廓重新摆进花束里，也不会用花朵拼成原图里的任何形状。

```text
参考图片
  ↓
色彩 / 粗略分区 / 密度 / 氛围
  ↓
脱离原图，只保留花束配方
  ↓
普通真实花束
  ↓
花束成品图 + 花艺师执行单
```

## 怎么用

安装 Skill 后，直接给 Codex 一张图片，例如：

> 用 image-to-bouquet 把这张图转成一束花。

不需要提前指定花材。Skill 会自己决定花材、包装、结构和整体配色。

参考图可以是人物、风景、建筑、插画、海报、专辑封面或抽象图片。

## 核心原则

### 最终必须还是“一束花”

结果默认是一束普通的手绑花束，而不是花艺装置或用花做成的图案。

即使参考图是一张人像，最后也只能留下它的配色和氛围，不能出现：

- 人脸或五官；
- 用花拼出来的人脸轮廓；
- 身体、建筑、物体或场景形状；
- 花朵马赛克、浮雕、肖像或图案；
- 原图文字、Logo、线稿或图形。

一个简单判断标准是：

> 把原图藏起来以后，花艺师应该只会说“这是一束花”，而不是“这束花摆成了某个东西”。

### 只保留粗粒度视觉关系

Skill 会优先保留：

1. 主色 / 次色 / 点缀色及大致比例；
2. 左冷右暖、中心亮边缘暗等粗略色彩分区；
3. 整体疏密、纵向或横向倾向；
4. 柔和、冷峻、热烈、克制等氛围。

不会保留原图主体的轮廓、局部边缘和内部结构。

### 先分析，再切断原图

分析完成后，Skill 会先生成一个只包含花材与配色的 **纯花艺配方**，之后再根据这个配方从零生成花束。

原图不应该继续作为编辑底图、贴图、纹理或构图模板参与最终图片生成。

这样可以避免模型把人物、建筑或封面图案偷偷带进花束。

### 色彩来自花本身

主要颜色必须来自真实花材、配叶、包装和丝带，而不是靠灯光“染色”。

最终图片采用接近正常花店商品照的灯光：

- 灯光在画面外；
- 不出现 LED、霓虹管、灯棒或灯泡；
- 不依靠强烈红蓝紫灯改变花材本色；
- 放到普通日光下，主要配色仍然成立。

### 只使用正常花艺材料

默认可见元素只有：

- 鲜花；
- 配叶和植物枝材；
- 必要时明确说明的干花 / 永生 / 染色 / 仿真植物材料；
- 普通花艺包装纸、内衬和丝带。

默认不加灯、支架、亚克力、吊牌、卡片、Logo、打印图片、抽象装置或其他为了“更酷”而出现的道具。

包装也应当像正常花店使用的柔性花纸，而不是海报、专辑封面或硬质展示板。

## 你会得到什么

### 1. 花束成品图

一张独立、清晰、真实的花束产品图。

花束应该满足：

- 看起来像真实花店能卖的成品；
- 花材、数量、结构和包装可以实际复现；
- 保留参考图最重要的色彩关系；
- 不形成任何人物、物体、符号或场景图案；
- 没有原图元素重复出现；
- 没有灯光、纸卡或概念装置替花材承担视觉效果。

### 2. 花艺师执行单

图片生成完成后任务还没有结束。Skill 必须继续提供与最终花束完全对应的执行单，包括：

- 尺寸与花束结构；
- 花材和配叶；
- 每种材料的大致数量；
- 包装和丝带；
- 简短制作顺序；
- 可替代材料；
- 成本等级；
- 最需要保留的色彩关系。

只返回图片、漏掉执行单，属于不完整结果。

## 默认控制成本

除非特别说明，默认做中小尺寸花束：

- 花材种类不过多；
- 主花数量适中；
- 优先使用常见、容易采购的材料；
- 能通过包装和少量配叶完成的颜色，不靠额外堆花解决。

目标不是复制原图，而是：

> **让人能感受到这张图的配色和气质，同时第一眼看到的仍然只是一束真实的花。**
